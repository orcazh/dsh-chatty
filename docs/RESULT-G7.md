# 结果：只在选定会话生效（G7）+ 缓冲式逐条显示（FR-1）

**日期**：2026-10-27
**DSH 版本**：0.2.1-rc.3
**结论**：**两项均已实机通过**

---

## 一、只在选定会话生效（G7 / FR-12）

### 结论

`conversation.chat.node` 这个 slot 在 DSH 里声明为 `scope: "session"`，
即**每个会话一个槽位实例**。`sessions.scope(会话id).get("slots")` 能拿到该会话的
slot 服务，**且它与根 slot 服务不是同一个对象**（实测 `sameSlotServiceAsRoot: false`）。

往它里面注册，就只会影响那一个会话：

| 场景 | 结果 |
| :--- | :--- |
| 选中的会话 | 气泡渲染 |
| 其他会话 | **完全不受影响**，原生渲染 |
| 切换会话再切回 | 气泡恢复（约 0.2–0.3 秒） |

### 三个必须知道的坑

1. **`sessions.retain()` 插件用不了。**
   它的 `source` 参数类型只允许 `"controllerOperation" | "gateway"`，第三方插件递不进去。
   想靠“保活”让会话作用域常驻，这条路堵死。

2. **切走会话时，作用域会被整个销毁。**
   我们的注册随之失效。这不是 bug，是 DSH 的正常生命周期。
   所以必须**在作用域重建时重新注册**。

3. **作用域对象的身份会变。**
   重建后 `sessions.scope(id)` 返回新对象，`get("slots")` 也是新的。
   用 `slotService !== 上次那个` 判断“是不是新作用域”，简单可靠。

### 实现方式

`scopedWatch(sessionId)`：每 250 毫秒检查一次作用域是否在位。

- 不在位 → 什么都不做
- 在位且槽位服务已变 → 先注销旧的，再注册新的

代价是切回会话时约 0.2–0.3 秒才出现气泡。**可接受，但不是最优。**
客户端 `sessions` 服务没有暴露作用域生命周期事件，轮询是目前唯一手段。
若将来找到事件钩子，应替换掉轮询。

## 二、缓冲式逐条显示（FR-1）

### 行为

| 阶段 | 表现 |
| :--- | :--- |
| 模型生成中 | **不显示正文**，只显示「正在输入」三点 |
| 生成结束 | 第一条气泡 200ms 后出现 |
| 气泡之间 | 显示三点，停顿后出下一条 |
| 历史消息 | 一次全部显示，不播动画 |
| 系统开启“减少动画” | 一次全部显示（尊重无障碍设置） |

间隔算法（按**即将出现的那一条**的字数）：

```
间隔 = bubbleGap(默认 450ms) + 字数 × PER_CHAR_MS(默认 6ms)
限制在 400–1200ms 之间
```

两项都可用 `__humanizeSpike.gap()` / `.perChar()` 即时调整，无需重启。
将来这是设置界面的两个滑杆。

### 三个坑（都踩过，都修了）

1. **生成结束的一瞬间，DSH 会把组件整个换掉。**
   流式投影和完成投影是两份数据，切换时会重新挂载组件。
   任何存在组件内部（`useRef` / `useState`）的“我见过它在流式”的记忆，
   **都会在这一刻丢失**，导致它把这条回复当成历史消息，一次性全画出来。
   → 记忆必须放在组件外（模块层），以 `turn:step` 为键。

2. **结束后的第一帧，正文是空的。**
   `status` 已经不是 `running`，但 `blocks` 还没填进来。
   如果此时判断 `已显示数(0) >= 总气泡数(0)` 成立，就会误判“播放完毕”，
   下一帧真正的正文到达时直接全量显示。
   → 空正文时必须判定为「等待」，绝不能判定为「完成」。
   这个判断已抽成纯函数 `nextRevealAction()`，并由 smoke 单测锁定。

3. **计时器不能绑在组件里。**
   组件每次重渲染，`useEffect` 的清理函数都会清掉上一次的 `setTimeout`。
   DSH 渲染很频繁，导致长间隔（如 900ms）**永远等不满**：
   第一条（200ms）能出来，第二条就卡死。
   → 计时器交给模块层的调度器，它只负责“通知”当前挂载的组件重画。

## 现状与遗留

**已可用的完整链路**（手动触发）：

```js
__humanizeSpike.setMode("off")                                  // 关掉全局
__humanizeSpike.scopedWatch("session-....")                     // 只在这个会话生效
```

**动画排查工具**：

```js
__humanizeSpike.diag()        // 配置 + 减少动画开关 + 所有节点的进度
__humanizeSpike.reveals()     // 只看进度表
__humanizeSpike.resetReveal() // 清空记忆，让旧消息也能重播
```

**待办**：目前仍要手动在 Console 里跑 `scopedWatch`。
产品化需要「启动时读配置 → 自动 watch 选定会话」，以及设置界面（D3）。
