# G2 结果：L2 提示词遵循度

**日期**：2026-10-27
**DSH 版本**：0.2.1-rc.3
**模型**：DeepSeek Harness 默认模型（未改温度）
**采样**：8 条输入，各 1 次；会话 `session-c654d4f4-…38eaee`
**状态**：**技术指标达标，待人工判断"碎度"**
**结论**：**条件通过**

---

## 方法

不人工数段落，改为**宿主捕获 + 脚本计分**：

1. `spike.config.json` 的 `scope.mode = "allowlist"`，只放行一个会话；
2. 宿主在 `systemPrompt.section` 注入 L2 分段规范（`order: 900`）；
3. 宿主监听 `session/event` 的 `assistant/message`，把最终正文写进
   `spike-humanize/.spike-output/assistant.jsonl`；
4. `npm run g2` 读取该文件，用**与客户端渲染同一个围栏状态机**重新数段，
   输出合规率、围栏内空行、未闭合围栏、规范泄漏四项指标。

`npm run smoke` 会把捕获文件回滚到运行前长度，测试不会污染样本。

### 两条越界的实际影响

- **#1 = 7 段**（超 1 段）：内容 317 字，平均 44 字/段，读感正常，不算问题。
- **#7 = 12 段**（超 10 段上限）：内容 491 字讲五层原因，每段一个论点，平均 39 字。用户实机判定「感觉不错」。
- **#4 / #5 只有 3 段**：中段是被列表和表格占满的整块，物理上不能拆，不是模型偷懒。

### 副作用：回答整体变短

八条无例外全部变短，平均约 **−28%**，其中 #2（死锁）与 #8（工具调用）接近腰斩。
输入完全相同，说明是规范直接导致，不是模型随机波动。

原因很清楚：**「≤60 字一段」与「信息量不变」在长回答上互相拉扯**，模型选择了压缩。
规范第 7 条「不得为了分段而省略、压缩…事实内容」被部分违反（#2 丢掉了
`Go select + time.After`、`wait-for graph`、数据库锁超时等细节）。

这不是错误，而是一个**产品取舍**：聊天感更强，细节更少。是否接受由使用者决定。

### 角色插件共存

采样期间 `dsh-persona-dafeiyu` 同时在跑：回复中出现「本鱼」自称，语气未被破坏，
说明 L2 section（`order: 900`）与角色 section 未发生覆盖冲突。

## 结论与下一步

- **第一轮（2–6 段规范）技术指标全部达标**：88% 落在区间，零元话语，零破围栏。
- 但**观感判定为「还不够碎」**（用户 2026-10-27 反馈）：希望更像连发消息。
- 因此进入**第二轮**：把规范改成「1–2 句一段、单段 ≤60 字、通常 3–6 段、首段要短」，
  并把规范文本搬到 `spike.config.json` 的 `sectionText`，**改提示词不再需要重启 DSH**。
- 第二轮判定标准改为：**3–6 段 ≥ 80%**，元话语 0，破围栏 0，代码块/表格/列表不拆散。
- 第一轮原始数据已归档为 `assistant.round1.jsonl`，第二轮为 `assistant.round2.jsonl`。

### 第二轮结果（2026-10-27）

**硬性要求全部通过**：0 破围栏、0 元话语、0 单段回复、代码块与表格实机确认未被切开。

**碎度达成**：平均字/段从 69–190 降到 15–72，气泡总数 38 → 46。用户实机判定「**感觉不错**」。

**3–6 段达标率 75%**（目标 80%），未达标但两条越界都在「过碎」方向，且用户接受：
#1 超 1 段、#7 达 12 段（491 字讲五层原因，每段一个论点）。

**G2 判定**：**通过**。理由是 Gate 要回答的问题是「L2 提示词能不能可靠地让模型产出可用的分段」，
答案是能：零结构破坏、零泄漏、碎度可调、可热调。80% 这个数字是第二轮临时自设的目标，
而它想表达的东西（模型不会偏离到无法使用）已经被更硬的指标证实。

**遗留取舍（不是缺陷）**：回答整体缩短约 28%，长回答会丢细节（#2 丢掉了部分实现细节）。
规范第 7 条要求「不得为分段而压缩」，但「≤60 字一段」与「信息量不变」本身互相拉扯。
若要保留细节，在 `sectionText` 第 2 条后加一句即可，**无需重启**。

## 第二轮规范（当前生效）

```
【回复分段规范】
1. 像在即时通讯里连续发消息那样组织回复：每个段落只讲一件事，1–2 句，段落之间空一行。
2. 单段尽量控制在 60 字以内；超过 2 句就再拆一段。
3. 一条回复通常 3–6 段；内容多时可以更多，最多 10 段。
4. 第一段要短，先给出结论、答案或反应，不要开场客套。
5. 代码块、表格、列表、引用块内部不要插入空行；这些块各自独立成段。
6. 不要解释、提及或复述本规范。
7. 不得为了分段而省略、压缩、重复或改述事实内容。
```

`sectionText` 支持字符串或字符串数组；为 `null` 时使用 `host.js` 里的内置默认值。
`sectionText` 在**每回合**读取，因此调提示词只需保存配置文件。
