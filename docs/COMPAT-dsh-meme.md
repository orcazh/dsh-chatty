# 与 `dsh-meme`（表情包）的兼容问题

**日期**：2026-10-28
**症状**：AI 发了表情包，图能正常出来，但**下面还留着一行 `[表情: …]` 说明文字，
而且不停闪烁**（一会儿在、一会儿不在）。
**结论**：不是 `dsh-meme` 坏了，是它的做法和「我们自己渲染气泡」这件事天然打架。
已在本插件侧修掉，不需要改 `dsh-meme`。

---

## 它到底是怎么出图的

`dsh-meme` 的客户端**不注册任何渲染槽位**，它靠**改写 DOM**：

1. 每 ~300ms 扫一遍 `document.body` 的文本节点，用
   `/\[表情:\s*([^\]]+)\]/` 找标记；
2. 找到就把那个文本节点换成 `<img data-meme-img>` + 一个 `display:none` 的
   ghost（ghost 里存原文，用来比对/去重）；
3. 把 `<img>` **提到整条消息行（`[data-chat-flow-key]`）的第一个子节点**，
   于是图出现在气泡**上面**（设置里的「独占一行」布局）；
4. 把中间那些「已经空掉」的层 `display:none` 掉 —— 也就是原来放标记文字的那块。

关键点：**它认的是「DOM 里有一个含标记的文本节点」**，而不是会话数据。
所以谁来画这段文字，它都会去抢。

## 为什么在我们这里会闪

我们把它当普通段落，**单独切成一个气泡**。于是那句话的 DOM 在我们手里：

- 插件第 4 步把我们的气泡 `display:none` 掉 → 文字消失；
- 我们这边 React 一重渲染，那个气泡节点被重建成新的（`data-meme-empty`
  和 `display:none` 都跟着旧节点没了）→ 文字又出现；
- 插件的下一轮扫描（≤300ms）再把它藏回去 → 再消失……

两边按各自的节奏各干各的，就是用户看到的「不停闪烁」。图之所以稳，是因为
它在**行元素**上，不在我们的 React 子树里。

## 改法：把自己那个气泡标记出来，用 CSS 让位

1. 渲染时识别「**整段只有一个标记**」的段落，给那个气泡加 `data-hz-meme="1"`；
2. 注入一条 CSS：

```css
[data-chat-flow-key]:has(>img[data-meme-img]) [data-hz-meme],
[data-time-hover-root]:has(>img[data-meme-img]) [data-hz-meme]{display:none!important}
```

为什么用 CSS 而不是 inline `display:none`：插件的清理逻辑会往
`el.style.display` 写回 `''`，一次扫描就把它推翻了 —— 那正是闪烁本身。
写在样式表里的 `!important` 插件碰不到。

为什么用 `:has(> img[data-meme-img])` 而不是无条件隐藏：**只有插件真的把图
放到了这一行，我们才让位**。三种反面情况都保持原文可见：

| 情况 | 表现 |
| :--- | :--- |
| 没装 `dsh-meme` | 没有图，气泡照常显示 `[表情: …]`（和以前一样） |
| 插件没匹配到图（描述对不上） | 插件会把标记降级成纯描述文字，我们照样显示 |
| 图是别的来源（不是 `data-meme-img`） | 不受影响 |

还有一层稳健性：`:has()` 认的是**行里有没有那张图**，不是我们气泡的节点身份。
所以即使 React 把气泡整块重建，只要图还在行里，新气泡**第一帧就是隐藏的**，
中间不会漏出一帧文字。

## 仍然存在的边界

- 标记**混在句子中间**（比如「好耶 [表情: x] 走起」）时，我们只标记整段是
  标记的那种气泡；混排的情况交给插件原地替换，不隐藏整个气泡。
- 图的位置由插件决定（行首、气泡上方），我们没法把它挪到「第几个气泡之间」。
- 插件扫描有 ~300ms 的节奏，所以新消息里图会比文字晚一点点出现，这是它自己
  的调度，不是我们的节流。

## 回归

`npm run smoke` 里新增一条断言：`前一句。\n\n[表情: …]\n\n后一句。` 必须切出
3 个气泡，且**只有中间那个**带 `data-hz-meme="1"`，普通气泡不能被标记。
